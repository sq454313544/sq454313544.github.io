## 问题背景

为了让经营看板不再依赖人工导出的 Excel，把三个外部来源接入了统一调度：工作手机系统、预测式外呼、在线回款表单。链路都是同一形态：

```text
采集（抓取/下载） → 落表（raw） → 校验 → 入库 → Airflow 每日调度
```

三条链路都"跑通了"，校验脚本也全绿。但一次针对 16 个脚本 + 4 个 DAG 的独立对抗性自查，查出 **12 类真问题**，其中**三条是静默数据错误**——任务成功、校验通过、数据是错的。

这篇笔记只讲这三条，以及它们共同的形状。

## 三个静默错误

### 一、字段名写错，而校验脚本用了同一个错名字

加载脚本把源字段写成了 `task_type`，而接口返回的实际字段名是 `type`。结果全表 **109/109 行 NULL**。

关键不在这个笔误，而在**校验脚本用了同一个错名字**：它读 `task_type`，库里也是 `task_type`，于是「库 NULL vs 源 None」判定相等，**逐格比对 0 差异、全绿通过**。

```python
# 旧：两侧共用错名，永远相等
assert row["task_type"] == source.get("task_type")   # 都是 None

# 新：显式 (源字段, 目标列) 映射 + 双向断言
FIELD_MAP = {"type": "task_type", ...}
assert set(source_fields) == set(FIELD_MAP)          # 接口字段必须全部被覆盖
```

修复后实测得到 105 个 `1`、4 个 `2`。

**教训**：校验脚本如果和加载脚本共用同一份字段名推断，它就退化成了**同义反复**——只能证明"代码和自己一致"，不能证明"数据和源一致"。字段映射必须是**显式成对的**，并且要断言"源侧字段一个不漏地被覆盖"。

### 二、失败被"洗白"成稳定状态，下一轮永不重拉

外呼采集按任务抓话单，结束后把每个任务的状态写进 `_state.json`；下一轮把状态为"稳定"的任务跳过。

缺陷是：**单个任务抓取失败之后，其状态依然被写进 state**。于是下一轮它被判为"稳定"、永不重拉；而 DAG 重试恰好跳过它，退出码 0 —— **失败变成了成功**。更糟的是 `calls.ndjson` 里已经缺了这个任务的数据，入库按 `task_id` **整段替换** ⇒ 库里该任务的历史话单被删掉且不会补回。

```text
采集失败 → 仍写 state → 下轮判"稳定"跳过 → DAG 重试也跳过 → 退出码 0 → 入库整段替换 → 历史话单丢失
```

修法两侧同时收口：

- 采集侧：**失败任务不写 state**，并从上一轮的旧文件里把它的话单搬回来；
- 入库侧：闸门从"全空才拦"改为**逐任务断言「已拨打必须有话单」**。

**教训**：状态文件是"跳过"的依据，所以**写状态必须在成功之后**。任何"先记账、后干活"的顺序，都会把失败固化成永久跳过。

### 三、容器时钟是 UTC，快照日期系统性错一天

每日快照的 `snapshot_date` 用 `date.today()` 生成，而 DAG 排在 07:30（北京）= **前一天 23:30 UTC**，于是每天的快照日期都指向前一天。

修正为**固定 +08:00 业务时区**，并在容器内实测验证。

**教训**：跨时区调度里，`today()` / `now()` 这类隐式本地时间都是隐患。调度表达式里的时间和业务日期必须是**显式的、带时区的**换算，而不是靠"机器应该在北京"。

## 共同的形状

三条错误放一起看，是同一个形状：**校验锚在了错误的对象上**。

| 错误 | 校验锚在哪 | 应该锚在哪 |
|---|---|---|
| 字段名写错 | 加载脚本自己的字段名 | 接口返回的真实字段集 |
| 失败被洗白 | 任务退出码 | 产物与声明的一致性（已拨打必须有话单） |
| 快照日期错一天 | 机器本地时间 | 带时区的业务日期 |

退出码、自己的字段名、机器本地时间——这三个都是**"看起来权威、实际不承载业务事实"**的锚点。

## 可复用的检查清单

1. **校验与实现分离**：校验脚本独立断言源侧结构（字段集、列序、非空率），不与加载脚本共用推断逻辑。
2. **状态只在成功后写**，并且失败时回搬上一轮产物，避免"整段替换"造成历史丢失。
3. **闸门逐实体而不是整体**：整体非空判断会被"部分成功"骗过。
4. **断言"必须恰好 N 个"**：例如云客接口必须恰好返回 71 个规范指标——少返回一个会让整列静默消失。
5. **显式时区**：业务日期一律用固定偏移换算，并留一次容器内实测。
6. **小样本阈值不能恒真**：阈值判断要能对 1 行样本也生效。
7. **隐私字段不入日志**：手机号、姓名、录音路径这类字段在日志侧加白名单守卫。
8. **自查要引入独立视角**：同样的思路复查自己的代码，会重复同样的盲区。

## 关于"全绿"

自查修复后，三条链路的校验结果是：云客逐格 5,893 × 2 格、外呼任务 3,815 格 + 话单 346,957 格、案件链全项通过。

这件事之后我调整了对"通过"的定义：**端到端成功说明链路活着，逐格一致只说明"和某一侧的某个视图一致"**。真正要证明的是——**它和源一致，并且在失败时不会静默变成成功**。
