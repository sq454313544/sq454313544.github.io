## 问题：为什么不让模型直接查询数据

模型生成的内容具有不确定性，而数据查询同时涉及权限、资源消耗和业务解释。即使模型“看起来知道”要查询什么，也不能因此获得任意执行权限。可靠的设计应当把模型放在理解和编排的位置，把数据访问收敛到唯一的受控入口。

## 核心结论：安全不是单点校验

Query MCP 的价值不在于增加一个接口，而在于把安全策略放到每次执行都必须经过的关口。任何单一规则都可能被绕过；多层约束共同决定一次请求是否允许执行、在什么范围内执行、如何记录结果。

## 先定义安全契约

受控查询入口应只接收结构化能力标识、经过类型约束的参数和可信权限上下文，不接收模型自由拼接的可执行语句。一个最小安全契约需要回答：

- 当前身份是否能看到并调用这项能力？
- 参数是否属于能力允许的类型、范围和枚举？
- 查询计划是否只引用已注册的数据对象与操作？
- 行级、字段级和结果规模限制在哪里强制执行？
- 失败、拒绝和成功分别记录哪些最小审计信息？

这些判断由执行层完成。模型可以提出计划，却不能为自己的计划签发通行证。

## 十层防线

### 1. 工具可见性

只向当前入口和用户暴露允许使用的工具。模型看不到的能力不能被自由文本强行调用，减少无意义或越权选择。

### 2. 工具权限

即使工具可见，也要按角色、场景和功能开关再次判断是否允许调用。可见性改善候选范围，权限校验才负责授权。

### 3. 可信用户上下文

身份和权限范围必须来自可信入口，并在调用链中保持完整。客户端自然语言、模型输出和缓存内容都不能自行声明或扩大权限。

### 4. 能力与对象白名单

查询只能引用 Registry 中已激活的能力、数据对象、维度和操作。未注册对象即使语法合法，也不能进入执行。

### 5. 参数与类型契约

指标、时间、维度、筛选值、分页和导出请求都必须遵循预设类型、范围与枚举。参数校验失败应回到澄清或修正，不应拼接字符串继续尝试。

### 6. AST、黑名单与 Schema 校验

对确定性模板形成的查询计划做语法树检查，拒绝写操作、危险函数和未授权对象，并确认引用字段属于当前 Schema。AST 是执行前的独立防线，不是让模型自由生成 SQL 的理由。

### 7. RLS 与字段范围

授权范围应在执行层统一注入，而非依赖调用者自觉传递。对返回行数、聚合粒度和超时设置上限，既控制风险，也避免一次请求占用过多资源。

### 8. 查询预算与资源护栏

对超时、返回行数、分页深度、导出规模、并发和重试次数设置独立预算。资源限制是安全边界的一部分，不能在模型要求“继续尝试”时自动放宽。

### 9. 最小权限只读执行

执行身份只保留完成查询所需的最小只读权限，并限制到必要的数据出口。模型、Plugin 和入口层都不持有数据库连接，也不能绕过 Query MCP 直连数据源。

### 10. 结果约束、追踪与审计

记录请求关联标识、能力、校验状态、RLS 是否应用、结果规模和执行状态，便于事后定位。导出与反馈使用同一追踪链，但不默认记录反馈正文、真实问题或完整结果。校验失败时返回稳定错误类型或澄清建议，而不是尝试“猜一个替代查询”。

## Prompt Injection 为什么不能越过执行边界

提示词注入首先影响的是模型输出，不应直接改变权限与执行策略。即使模型被诱导请求未授权能力，Query MCP 仍只认可信身份上下文、Registry 白名单和参数契约。

真正需要警惕的不是某一句“忽略之前规则”，而是系统是否存在绕过受控入口的旁路，例如把自由文本直接交给数据库驱动、允许客户端声明权限，或在校验失败后自动放宽范围。消除旁路比继续堆叠提示词更重要。

## 失败应如何分类

安全失败不应全部包装成“查询出错”：

| 类型 | 处理方式 |
|---|---|
| 能力不可见或权限不足 | 拒绝执行，仅说明可公开的边界 |
| 候选不唯一或必要参数缺失 | 请求用户澄清 |
| 参数、语法或对象不合法 | 阻断并记录校验原因 |
| 超时、分页或资源预算超限 | 安全终止，可建议缩小范围 |
| 下游暂时不可用 | 保留可重试状态，不自动更换业务口径 |

清晰分类既改善用户体验，也让监控能够区分产品理解问题、安全拦截和基础设施故障。

## 常见追问

### 为什么数据库权限不足以解决所有问题？

数据库权限是最后一道底线，但它不知道一次自然语言请求对应的业务能力、参数意图和产品规则。应用层控制补足了工具可见性、参数验证、RLS、资源预算和审计语义；最小权限账号则限制旁路或上层缺陷的最大影响范围。

### 如何应对提示词注入？

不要把安全决策交给提示词。即使模型被诱导改变输出，受控执行层仍需独立验证能力、权限、参数和语法；不满足规则的请求不能进入执行。

### 审计记录什么才有用？

记录足以复现决策过程的最小信息，例如关联标识、能力版本、请求时间、校验状态、RLS 应用状态、授权范围摘要和结果规模。避免默认记录用户的敏感原始内容、反馈正文、完整权限或真实业务结果。
