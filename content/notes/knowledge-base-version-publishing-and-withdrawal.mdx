> 文中制度、编号与代码均为教学示例。

把文档切片并放进检索库，只完成了资料接入。员工问“现在应该怎么做”时，还需要判断：这份资料有没有发布、是不是当前版本、这个人能不能看。

本文用一份虚构的《设备借用流程》，推演资料更新与撤回。示例规则不对应真实公司的制度。

## 30 秒速览

- 资料存在于存储或检索索引中，不等于可以用于回答。
- 文档身份、原文版本与发布批次解决三个不同问题：是哪份资料、是哪次内容、当前允许使用哪些内容。
- 更新与撤回需要同时影响检索、会话和出处。不能只修改标题，或只告诉模型“不要用旧版”。

这里讨论文档知识库的资料治理。智能问数中的表、指标和能力检索，还需要数据权限、口径与查询校验，不能直接套用本文的文档示例。

## 先分清三个编号

| 对象 | 示例 | 回答的问题 |
| --- | --- | --- |
| 文档身份 | D-001 | 这是哪一份流程资料？改版后仍是同一份资料吗？ |
| 原文版本 | D-001@V1、D-001@V2 | 当时具体写了什么？答案引用的是哪个内容版本？ |
| 发布批次 | B1、B2、B3 | 当前问答允许从哪些版本中找依据？ |

这里把“发布批次”理解为一份可追溯的可用版本清单。一个批次可以包含多份资料。本文只用一份资料演示，真实清单还需要考虑适用范围、访问权限和生效时间。

原文版本应保留内容身份，不能在同一个版本号下悄悄替换正文，否则历史回答中的“引用 V1”将无法说明当时看过什么。

## 从 V1 发布，推演到 V2 撤回

假设 V1 写着“提前 1 个工作日申请”，V2 改为“提前 2 个工作日申请”。

| 阶段 | 存储或索引中的资料 | 当前发布清单 | 新问题应怎样回答 |
| --- | --- | --- | --- |
| V1 已发布 | V1 | B1：V1 | 提前 1 个工作日，并引用 V1 |
| V2 已准备，尚未发布 | V1、V2 | B1：V1 | 仍依据 V1；V2 不能因检索命中就进入答案 |
| V2 发布并替代 V1 | V1、V2 | B2：V2 | 提前 2 个工作日，并引用 V2 |
| V2 被撤回 | V1、V2 可能仍保留 | B3：本例无可用版本 | 说明没有可用的已发布依据，不再给出 1 天或 2 天的结论 |

最后一行最容易误判：V2 被撤回，不代表 V1 自动恢复有效。撤回可能意味着整个流程需要重审，而不只是新文件上传错了。

如果资料负责人确认应恢复 V1，应把恢复作为一次明确发布：重新核对 V1 的适用性、权限和生效条件，形成 B4 的清单。这个治理选择用于本例，实际系统应由业务方明确回退规则。

## 一个能自己运行的过滤练习

下面的 Python 示例只演示“从候选结果中筛出当前可用依据”。它不调用模型、向量库或真实 WeKnora 接口，也不实现并发发布。

`allowed_versions` 和 `user_scopes` 在真实系统中应由服务端依据发布记录与身份权限得到，不能信任员工从客户端提交的值。

将下面代码保存为 `.py` 文件，用 Python 执行即可核对输出。

```python
def select_evidence(hits, allowed_versions, user_scopes):
    return [
        hit
        for hit in hits
        if hit["version_id"] in allowed_versions
        and hit["scope"] in user_scopes
    ]


hits = [
    {
        "version_id": "D-001@V1",
        "scope": "staff",
        "text": "提前1个工作日申请",
    },
    {
        "version_id": "D-001@V2",
        "scope": "staff",
        "text": "提前2个工作日申请",
    },
]

published = {
    "B1": {"D-001@V1"},
    "B2": {"D-001@V2"},
    "B3": set(),
}

for batch_id, allowed_versions in published.items():
    evidence = select_evidence(hits, allowed_versions, {"staff"})
    version_ids = [item["version_id"] for item in evidence]
    print(batch_id, version_ids)

print("无权限", select_evidence(hits, published["B2"], set()))
```

预期输出：

```text
B1 ['D-001@V1']
B2 ['D-001@V2']
B3 []
无权限 []
```

代码没有删除 V1、V2，却能让 B3 无可用依据。它说明“保留历史文件”和“允许当前问答使用”可以分别管理。物理清理仍有自己的保留和删除规则。

这个函数只判断资料能否作为候选依据，并不判断它是否回答了当前问题。例如，设备借用流程虽然允许读取，也不能据此回答“设备维修由谁批准”。还需要核对相关性、适用条件和答案是否被原文支持；没有充分依据时，应返回无依据或条件不足的状态。

真实检索应尽量在召回时应用权限与发布范围，再在组装模型上下文前核验候选。仅在取回少量结果后过滤，既可能让未授权正文先进入处理链，也可能漏掉排名稍后的有效资料。

## 发布时，哪些步骤需要一起生效

在这个设计中，发布前先完成原文登记、解析、索引准备和必要检查，再进入受控切换。数据库内的批次记录与当前指针需要作为一个事务提交，避免读到“新指针、旧清单”的半次更新。

事务可以让同一数据库中的一组修改整体提交或回滚。[PostgreSQL 事务教程](https://www.postgresql.org/docs/18/tutorial-transactions.html)

但这个保证不自动覆盖外部检索索引与缓存。因此还需要发布锁、维护窗口、索引就绪检查，以及按批次区分缓存。失败时应保持一致的可用状态，或继续处于维护态，不能清掉报错就宣称发布完成。

对正在进行的问答，本文选择受控切换：先阻止新请求进入旧批次，等待旧批次请求完成，或取消并确认它们已停止输出，再切换当前批次。若请求异常地跨越了切换边界，发现依据失效时应终止本次回答，并在新批次下重新提问或重试。仅在输出前比较一次批次号，不能保证检查之后不会再次切换。

流式回答已经送到员工屏幕上的文本，后续撤回无法收回。系统可以停止后续输出并提示重新提问，但不能宣称已经发送的内容也被撤销。上面的过滤函数只验证候选筛选，不证明并发切换与流式输出的这些机制已经实现。

## 旧会话和出处怎样处理

旧答案可以作为“当时基于 B1、V1 产生的记录”保留，但不应继续作为当前规则复用。

是否继续向员工展示历史答案，也应按当前访问策略判断。保留审计记录，不等于原员工一直拥有阅读权限。

我采用的处理思路是：发布依据变化后，旧会话转为只读，提示“依据已更新”，新问题进入新的依据批次。撤回资料的入口应显示“已撤回”，不能通过旧引用绕过当前权限返回正文。

出处至少应能定位文档身份、原文版本和引用片段，并关联回答使用的发布批次。能定位来源，不代表已经完成受控的原文查看，也不代表模型的解释必然正确；是否准确理解了条款，还需要验收题与人工核对。

## 怎样验收“不会引用旧版”

不要只问一次“新版是什么”。至少检查：新版准备但未发布、新版替代旧版、撤回后无依据、旧会话继续提问，以及问答期间发生发布切换。

每个场景同时看三件事：检索选中了哪些版本、回答实际引用了哪些版本、员工是否能通过出处访问当前不允许看的内容。召回命中新版，但模型仍沿用历史答案，也算失败。

## 自测：先答，再展开

### 1. V2 已成功解析并进入向量索引，员工现在就应该按 V2 得到答案吗？

<details>
<summary>查看参考答案</summary>

不一定。解析和索引准备是接入状态，是否可用由当前发布清单、适用条件和员工权限决定。如果当前仍是 B1，只能使用 V1。

</details>

### 2. 为什么撤回 V2 后，不直接回到 V1？

<details>
<summary>查看参考答案</summary>

撤回 V2 不能证明 V1 仍然有效。本例要求恢复旧版也经过明确审核与发布，留下新的清单与原因。业务可以制定其他回退规则，但应把规则写清楚，而不是让检索结果或模型自己决定。

</details>

### 3. V2 还留在索引里，会不会必然导致撤回失败？

<details>
<summary>查看参考答案</summary>

不必然。是否失败取决于当前问答能否把它作为依据，以及访问接口是否仍返回不允许的正文。发布过滤、权限核验和上下文组装需要一致执行；物理删除不是唯一的可见性控制方式，也不能代替完整权限检查。

</details>

### 4. 请求按 B1 检索，在回答输出前系统发布了 B2，应该怎样处理？

<details>
<summary>查看参考答案</summary>

正常切换应先完成或确认中止旧请求，再推进批次。如果请求已经跨越 B2 的切换边界，应停止使用 V1，在 B2 下重新检索。已发送的流式片段无法收回，只能中断后续输出并明确提示；单次批次比较不能代替在途请求的协调机制。

</details>

### 5. 当前无可用依据，但模型从历史聊天里记得“提前 1 天”，可以回答吗？

<details>
<summary>查看参考答案</summary>

不能把历史记忆当作当前已发布依据。应返回没有可用依据的状态，并按约定引导确认资料；若存在范围不同的已发布候选，可给出带出处与适用条件的候选。不能为了让回答显得完整而补出一个确定规则。

</details>
