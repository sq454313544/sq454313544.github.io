## 项目背景

随着 AI Agent 在生产环境的部署，传统的服务监控无法覆盖 Agent 特有的问题：幻觉、Token 消耗异常、工具调用失败等。

## 业务问题

- Agent 行为不可观测，出现问题时难以定位
- Token 用量无法追踪，成本不可控
- 缺乏 Agent 级别的 SLA 监控

## 目标用户

- Agent 开发和运维团队
- 平台 SRE 团队

## 解决方案

构建 Agent 专用的可观测性系统：

1. 在 Agent 框架层埋点
2. 通过 OpenTelemetry 统一采集
3. Prometheus + Grafana 可视化
4. 告警规则覆盖 Agent 特有指标

## 核心功能

- **调用链追踪**：完整的 Agent 决策路径可视化
- **Token 监控**：按 Agent、按用户、按时段的 Token 消耗
- **错误分析**：工具调用失败率、重试次数、最终成功率
- **性能面板**：首 Token 延迟、端到端响应时间
- **告警**：异常 Token 用量、错误率飙升、响应超时

## 技术选型

- OpenTelemetry：统一的可观测性标准
- Prometheus：时序数据库，强大的查询语言
- Grafana：灵活的可视化面板

## 关键难点

1. Agent 调用链数据量大，需要有效的采样策略
2. 不同 Agent 框架（LangGraph、CrewAI）的埋点方式不同

## 项目结果

- Agent 问题定位时间从小时级降至分钟级
- Token 成本追踪覆盖率从 0 到 100%
- 提前发现多起潜在的生产问题

> 以上数据为模拟效果。

## 复盘

OpenTelemetry 的 Agent 语义约定还不够成熟，部分指标需要自定义。未来可以贡献到社区。
