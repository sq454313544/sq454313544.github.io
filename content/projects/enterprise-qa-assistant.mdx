## 项目背景

当业务人员需要获取指标或明细时，往往需要在多个系统、口径说明和人工取数之间反复确认。这个项目的目标不是让模型直接访问数据，而是建立一条可解释、可校验、可审计的自然语言问数链路。

## 目标与边界

- 支持指标查询、受控明细查询、指标解释、上下文追问和结果导出。
- 将指标定义、可用维度和查询模板收敛为可维护的 Registry。
- 让 Agent 负责理解、路由与解释；让受控执行层负责校验、查询和导出。
- 不向公开站点披露业务名称、数据对象、账号、原始 SQL 或真实查询结果。

## 核心设计

### Registry First

将指标口径、允许维度、明细映射与查询模板纳入统一注册表。每个问题先定位可用能力，再进入受控执行，避免仅靠 Prompt 推断业务含义。

### 受控查询边界

- 使用只读权限与参数校验约束查询入口。
- 通过 AST 校验、白名单、危险语句拦截和返回量限制控制风险。
- 在执行前注入权限范围，在执行后保留审计信息。
- 将文件导出从 Agent 编排中拆出，由独立能力处理鉴权与结果交付。

### 可追问的结果解释

会话上下文保留问题、已选指标和已返回结果的必要摘要；追问仍需经过能力匹配与校验，不复用未经确认的查询计划。

## 验证与当前状态

- 使用 50+ 条离线评测样本验证意图路由与候选检索。
- 检索 Recall 从约 40% 提升至 80%+，MRR 从约 0.41 提升至约 0.83。
- 补充 100+ 自动化测试，覆盖关键路由、校验和失败降级。
- 已完成测试环境端到端验收，当前处于小范围内测阶段。

## 复盘

智能问数的稳定性不来自“更长的 Prompt”，而来自可维护的口径注册、确定性查询边界和可回溯的验证流程。后续迭代会继续围绕评测覆盖、能力变更和异常降级完善工程质量。
