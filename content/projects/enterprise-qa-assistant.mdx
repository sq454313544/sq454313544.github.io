## 项目背景

业务人员在日常工作中经常需要查询数据，但 SQL 的学习成本高，每次临时查询都需要数据分析师介入，响应周期长。

## 业务问题

- 业务人员无法自助查询数据
- 数据分析师被大量临时取数请求占用
- 查询口径不一致，不同人对同一问题可能给出不同答案

## 目标用户

- 运营、产品、销售等非技术业务人员
- 需要快速获取数据的各级管理者

## 解决方案

构建一个自然语言查询 Agent，用户用中文描述问题，系统自动：

1. 理解用户意图
2. 映射到数据库表和字段
3. 生成并执行 SQL
4. 将结果可视化为图表

## 核心功能

- 自然语言转 SQL（NL2SQL）
- 多轮对话上下文理解
- 查询结果自动可视化（表格、柱状图、折线图）
- 查询历史与收藏
- 敏感数据访问控制

## 技术选型

| 组件 | 技术 | 理由 |
|------|------|------|
| Agent 框架 | LangGraph | 状态图适合多步推理 |
| 向量检索 | ChromaDB | 轻量级，适合中小规模 |
| 后端 | FastAPI | 高性能异步 |
| 前端 | Next.js | SSR + 良好的开发体验 |

## 关键难点

1. **Schema 映射准确性**：数据库有数百张表，需要精确地将用户问题映射到正确的表和字段
2. **SQL 正确性**：生成的 SQL 必须语法正确且语义准确
3. **查询性能**：自动生成的 SQL 可能不是最优的，需要优化

## 安全与治理

- 只读数据库连接
- SQL 白名单校验（禁止 DROP/DELETE/UPDATE）
- 敏感字段访问控制
- 查询审计日志

## 项目结果

- 临时取数请求减少约 60%
- 平均查询响应时间从 2 小时降至 2 分钟
- 查询口径一致性明显提升

> 以上数据为模拟效果，非真实业务数据。

## 复盘

1. Schema 映射是最大的技术挑战，后续计划引入 Few-shot 示例提升准确率
2. 用户反馈的查询意图识别需要持续优化
3. 可视化能力可以进一步增强（支持更多图表类型）

## 后续计划

- 接入更多数据源（MySQL、ClickHouse）
- 支持跨表联合查询
- 增加查询推荐功能
