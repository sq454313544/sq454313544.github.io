## 项目背景

当业务人员需要获取指标或明细时，往往需要在多个系统、口径说明和人工取数之间反复确认。这个项目的目标不是让模型直接访问数据，而是建立一条可解释、可校验、可审计的自然语言问数链路。

项目已从双入口问数 MVP 演进到内部 Pilot：除查询能力外，当前重点包括元数据版本治理、确定性评测、运行时保护、检索回退和正式放量前的质量门。

## 产品目标与边界

- 支持指标查询、受控明细查询、指标解释、上下文追问和结果导出。
- 通过企业微信和 Web 双入口提供流式响应，并保持一致的查询与权限边界。
- 将指标、维度、明细和 Prompt 等语义资产纳入可发布、可回退的治理链路。
- 让 Agent 负责理解、编排与解释；让受控能力负责校验、查询、导出和审计。
- 当前只进入受控内部 Pilot，不将内部测试结论外推为业务试运行或正式生产成果。
- 不向公开站点披露业务名称、数据对象、账号、原始 SQL、真实问题或查询结果。

## 我的职责

我负责产品设计、架构设计与核心开发，将自然语言取数需求拆解为可验证的产品和工程边界：定义可查询能力，梳理指标与元数据入口，并把路由、权限、校验、流式响应、结果导出、审计和评测串成可维护的交付链路。公开案例只展示通用架构与脱敏结果，不暴露内部能力标识、数据库对象或真实用户请求。

## 核心设计

### Registry First 与元数据控制面

运行时 Registry 管理 16 个业务指标及维度、明细映射；元数据控制面进一步形成 32 项语义资产基线，为资产生成稳定标识、版本和内容摘要。发布链路先校验权威数据契约，再生成运行时快照和检索索引；查询时若索引不可用，同次请求回退到已验证的 Registry，而不是使用未知版本继续执行。

完整定义按真实使用场景渐进补充。使用反馈先进入待确认清单，确认后先更新数仓权威契约，再派生运行时副本，避免助手反向成为业务口径的事实源。

### 分层执行与 SQL 零信任

- Agent 只能选择已注册能力并输出结构化参数，不生成或执行自由 SQL。
- 能力可见性、用户上下文、参数类型、白名单、AST、危险语句、Schema、RLS、返回规模和只读权限组成多层执行边界。
- 查询、导出和反馈都保留最小必要的追踪与审计信息，不默认记录原始敏感问题、完整结果或权限明细。
- 文件导出独立处理鉴权、结果集有效期与行数预算，不复用数据库直连能力。

### 检索策略与可回退 Pilot

早期基于 51 条离线评估集改进查询规范化和候选融合，将阶段性 Recall 从 39.22% 提升至 82.35%，MRR 从 0.412 提升至 0.833。这组数据描述的是 P0–P3 离线检索演进，不代表当前真实使用效果。

后续评估表明，单纯增加本地向量模型或 CPU Reranker 会带来不可接受的延迟，因此没有把它们写入现行主链路。当前内部 Pilot 使用带关键词证据、类型约束、候选去重和覆盖分配的受控混合检索；预热、权限、审计或依赖不满足时立即回退关键词链路。是否正式放量由真实样本质量、关键错误数和延迟 Gate 共同决定。

### 确定性评测与运行时加固

- 建立 20 条合成高风险确定性回放，覆盖协议、决策、安全边界和敏感信息扫描，当前结果为 20/20。
- 全量自动化回归超过 400 项，覆盖路由、Registry、MCP、权限、查询、导出、并发和失败降级。
- 请求追踪贯穿入口、Agent、Query MCP、结果集和审计，便于定位一次请求的完整路径。
- 增加消息原子去重、入口与查询并发护栏、慢查询记录、SSE 心跳、长任务状态和可恢复失败反馈。

确定性回放与自动化测试用于证明工程契约没有回归，不能替代真实模型质量、真实用户反馈或业务验收。

- 双入口和 Metadata、Query、Export MCP 的端到端集成已经完成。
- 元数据控制面阶段性能力、运行时加固、确定性回放和受控混合检索已具备内部测试条件。

## 关键决策与取舍

### 为什么不能只看 Recall

离线 Recall 能说明候选覆盖是否改善，却不能证明权限、参数、执行、解释和延迟都正确。当前把离线检索、确定性回放、全量回归和 Pilot 真实样本分开记录，避免用单一高分掩盖端到端风险。

### 为什么检索必须能够回退

语义检索依赖模型、索引、网络和预热状态。它可以提高候选覆盖，但不能成为受控查询的单点故障。回退链路保留关键词证据、Registry 版本和权限边界，使增强能力失败时系统仍能安全拒绝、澄清或执行已知能力。

### 为什么内部测试不等于正式放量

代码门禁通过只能说明当前工程基线可运行。真实表达分布、权限组合、异常网络和业务接受度仍需通过受控 Pilot 验证，达到预设 Gate 后还要独立评审。

## 复盘

智能问数的稳定性不来自“更长的 Prompt”或“更多模型组件”，而来自权威口径、版本化元数据、确定性执行、可回退检索和可追溯评测。当前工作的重点已经从功能可用转向证明它在真实约束下能够安全、稳定地运行。
