## 业务背景

随着多个 AI Agent 上线运行，运营团队需要实时监控各 Agent 的健康状态和资源消耗。本看板使用模拟数据展示 Agent 监控的典型视图。

## 核心指标

| 指标 | 目标 | 当前（模拟） |
|------|------|-------------|
| Token 消耗（日） | < 500K | 320K |
| 首 Token 延迟（P95） | < 3s | 2.1s |
| 端到端延迟（P95） | < 15s | 8.5s |
| 工具调用成功率 | > 95% | 97.2% |
| 错误率 | < 2% | 1.3% |

## 监控维度

### 1. Token 消耗趋势

按 Agent 维度和时间维度的 Token 消耗趋势分析，识别异常消耗。

### 2. 延迟分析

首 Token 延迟和端到端延迟的 P50/P95/P99 分布，定位性能瓶颈。

### 3. 错误分布

按错误类型（工具调用失败、超时、模型限流）分类统计。

## 结论和建议

1. 智能问数 Agent 的 Token 消耗占总量 60%，可考虑缓存常用查询结果
2. 晚高峰（18-21 点）延迟明显升高，建议扩容或限流
3. 工具调用失败主要由外部 API 超时引起，建议增加重试机制

> 以上数据和结论均为模拟，不代表真实业务情况。
