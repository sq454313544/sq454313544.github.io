# 真实内容与在线简历更新方案

> 版本：v1.1
> 日期：2026-07-28
> 状态：已完成；C0–C4 已通过内容质量门
> 执行顺序：C1–C4 内容更新 → M5 视觉 QA → D1–D4 GitHub Pages

## 一、目标

用可验证、可公开、经过脱敏的真实经历与项目实践替换当前网站中的通用个人资料、模拟项目和模拟 BI 案例，并将已有的技术问答整理为专题笔记。

本轮完成后，公开访客应能清楚理解：

- 个人定位、工作经历、教育背景与联系方式。
- 数据产品、Power BI、数据工程与 AI 数据应用能力。
- 智能问数、数据仓库重构和 BI 分析的真实交付方法。
- Registry First、MCP、受控查询和确定性执行的工程思路。

## 二、事实来源与优先级

允许使用的来源类别：

1. 最新项目状态、验收记录和测试报告。
2. 当前有效的项目 README、架构、路线图和技术设计。
3. Power BI 模型说明与迁移验证记录。
4. 数据仓库分层、契约、质量和调度说明。
5. 个人简历。
6. 技术面试题与回答整理。

事实冲突时按上述顺序处理。最新项目验收记录高于简历中的旧数字；只有单一自述、无法从项目资料验证的成果不作为公开事实。

严禁把以下文件作为公开内容直接复制：

- 环境变量、账号、密钥、私钥和连接配置。
- 原始 SQL、数据字典、内部库表字段和业务映射。
- 周报、原始 Excel/CSV、业务明细和运行日志。
- 内部截图、私有仓库地址和本机绝对路径。

## 三、公开与脱敏规则

### 允许公开

- 真实姓名。
- 所在城市。
- 简历中指定的求职邮箱。
- 学校、专业、学历和教育时间。
- 真实岗位名称与任职时间。
- 经验证后取整的项目规模和效果。
- 通用技术栈、架构方法、测试方法与工程复盘。

### 必须泛化或删除

- 手机号不公开。
- 任职单位统一泛化为行业或公司类型。
- 客户、资方、员工、案件和内部系统名称全部删除或泛化。
- 内部数据库、Schema、表名、字段名、URL、端口和账号不公开。
- 真实金额、案件量、人员绩效和业务明细不公开。
- 私有项目不提供 repository 或 demo 链接。
- 难以验证的个人估算不写入首页、简历或项目成果。

### 数字表达

公开数字必须有项目资料支持，并采用保守取整：

- 使用“约”“超过”“百余”“50+”“100+”“250+”等表达。
- 百分比可以用区间或整数级变化描述。
- 不把测试快照值、尚未完成的人工验收或未来规划写成已完成成果。
- 所有 BI 图表使用脱敏模拟数据，并在正文中明确声明。

## 四、个人资料与简历映射

`profileData` 更新范围：

- `profile`：真实姓名、数据产品工程师定位、BI / AI 数据应用方向、长沙。
- `heroSkills`：数据产品、Power BI、数据工程、智能问数、SQL、Python。
- `workExperiences`：三段真实时间和岗位，单位名称泛化。
- `skills`：数据产品与 BI、AI 数据应用、数据工程底座、AI 辅助研发。
- `toolsAndTech`：数据分析、AI 数据应用、数据工程与工程质量。
- `contacts`：仅保留邮箱。
- `education`：学校、专业、学历和时间。
- `projectHighlights`：智能问数与数据仓库重构两个真实案例。

页面映射：

- 首页读取真实姓名、职业定位、简介和 `heroSkills`，不再硬编码通用身份。
- About 展示三段经历、能力边界、技术栈、兴趣和邮箱。
- Resume 展示经历、项目、能力、教育和邮箱；无认证时不显示空认证区域。
- Resume 打印版不得打印手机号或任何内部信息。
