## 关键设计决策

### 1. Server Component 优先

所有页面默认为 Server Component。仅在以下情况使用 Client Component：
- 需要浏览器 API（ECharts、Mermaid 渲染）
- 需要交互状态（搜索输入、筛选切换）
- 使用 `"use client"` 库

### 2. 内容与渲染解耦

- `content/` 目录存储原始 MDX 文件（数据 + 内容）
- `lib/content/` 提供统一查询接口（Schema 校验 + 过滤 + 排序）
- 页面和组件只通过 Queries 获取数据，不直接扫描文件系统
- 后续更换渲染方式或视觉设计不影响内容系统

### 3. 构建时校验

所有内容在构建时通过 Zod Schema 校验：
- 必填字段缺失 → 构建失败（含文件路径和字段名）
- 字段类型错误 → 构建失败
- slug 重复 → 构建失败
- 非法枚举值 → 构建失败

这确保内容质量在部署前就被捕捉，而非运行时才发现。

### 4. 搜索无外部依赖

搜索索引在构建时从内容服务层生成，存储在内存中。搜索匹配在请求时完成。优点：
- 零外部服务依赖
- 搜索逻辑可单测
- URL 参数恢复搜索状态
- 数十到数百篇内容的场景下性能充足

### 5. 组件边界

```
components/
├─ content/      # 内容渲染组件（ToC、PrevNext、Related）
├─ navigation/   # 全局导航（Header、Footer）
├─ charts/       # 图表客户端封装（ECharts、Mermaid）
├─ seo/          # SEO 组件（JsonLd、Meta）
└─ primitives/   # 通用状态组件（Loading、Empty、Error）
```

每个组件：明确 Props + 可选 className + 语义化 HTML，按职责支持对应状态（数据列表=normal/empty, 图表=loading/normal/error/empty, 纯展示=normal）。

## 技术债务与后续演进

| 项目 | 当前 | 后续 |
|---|---|---|
| 搜索 | 内存匹配 | 可替换为 Meilisearch/Algolia（内容量大时） |
| Agent | 占位页面 + 接口类型 | 接入 FastAPI + LangGraph 后端 |
| 视觉 | 中性骨架 | 品牌设计系统 |
| 内容管理 | 手动编辑 MDX | 可选 CMS 后台 |
| 部署 | 本地通过 | Vercel / 自托管 |
| 分析 | 无 | GA / Plausible |
