# M1.5 MDX 管线 POC 报告

> 日期：2026-07-27
> 结论：通过，Shiki、Mermaid fenced code 分流与静态 TOC 可进入后续笔记视觉切片。

## 验证范围

在真实项目配置中临时创建 `content/notes/__poc__.mdx` 与 `app/dev/poc/page.tsx`。POC 验收完成后已删除两者；保留可用的组件实现与本报告。

| 能力 | 实现 | 验收结果 |
|---|---|---|
| Shiki | `PreCodeBlock` 在服务端用 `codeToHtml(code, { lang, theme: "github-dark-dimmed" })` 渲染 | TypeScript 代码块高亮成功，复制按钮可读取原始代码 |
| Shiki 回退 | Shiki 失败时渲染深色等宽纯文本代码块 | 代码不因高亮失败而丢失 |
| Mermaid fenced code | `language-mermaid` 在 `PreCodeBlock` 中优先分流到客户端 `MermaidDiagram` | 合法 flowchart 成功生成 SVG |
| Mermaid 失败回退 | 渲染失败时显示错误提示和原始 Mermaid 代码 | 无效 Mermaid 不阻塞正文 |
| Heading / TOC | 保留 `rehype-slug`；`extractToc` 为重复标题生成 `-1` 后缀 | POC 重复标题得到 `重复标题` 与 `重复标题-1`；真实笔记页的所有 TOC 链接均找到对应标题 |

## 浏览器验收

在独立的本地生产服务器与系统 Chrome 中完成以下检查：

- 复制按钮将 `export const answer = 42;` 写入剪贴板。
- 合法 Mermaid fenced block 生成 SVG。
- 无效 Mermaid 显示回退提示及唯一的原始代码块。
- 重复标题 ID 不冲突，页面在 390px 视口无横向溢出。
- 真实 `/notes/langgraph-state-nodes` 页面中的 TOC 链接全部命中 `rehype-slug` 生成的锚点。
- `pnpm test:e2e` 使用单个 worker 运行 16 条关键路径；这样可规避 Next 开发服务器在多 worker 并发请求下的 JSON 解析竞态。

## 后续约束

- Mermaid 必须在 Shiki 之前分流。
- 搜索管线不在本轮修改。
- 复制成功提示使用 `aria-live="polite"`；静态 Mermaid / Callout 不使用 live region。
- M2 仅在此实现基础上调整笔记视觉和布局，不重复建设代码、图表或目录基础设施。
